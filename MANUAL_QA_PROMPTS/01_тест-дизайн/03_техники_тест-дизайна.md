# Техники тест-дизайна

Классические техники — анализ граничных значений, переходы состояний, таблица принятия решений — в виде готовых промптов.

> **Как использовать:** скопируйте промпт, замените плейсхолдеры в `[КВАДРАТНЫХ СКОБКАХ]`. Результат всегда проверяйте — финальное слово за тестировщиком.

---

## 1. Анализ граничных значений (BVA)

**Зачем:** граничные значения — самые дефектоносные точки ввода; получить системный набор «Min−1 … Max+1».

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/test-case-creation/edge-case-prompts.md` + табличный формат из [Хабра](https://habr.com/ru/articles/986376/) — переведено на русский.

```text
Составь тест-кейсы методом анализа граничных значений (boundary value analysis).

Фича: [НАЗВАНИЕ]
Поля ввода:
- [ПОЛЕ_1]: тип [ТИП], диапазон [MIN–MAX], формат [ФОРМАТ]
- [ПОЛЕ_2]: тип [ТИП], диапазон [MIN–MAX], формат [ФОРМАТ]

Создай тест-кейсы для:
- минимальных и максимальных граничных значений;
- значений чуть ниже минимума (невалидные);
- значений чуть выше максимума (невалидные);
- точных граничных значений;
- комбинаций граничных значений разных полей.

Формат — таблица:
«Параметр | Min−1 | Min | Min+1 | Номинал | Max−1 | Max | Max+1 | Ожидаемый результат | Риск».
```

## 2. Тестирование переходов состояний (State Transition)

**Зачем:** проверить все разрешённые переходы и попытки «запрещённых» — для статусов заказов, платежей, заявок.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/test-case-creation/functional-prompts.md`, промпт «Workflow State Transition Testing» — переведено на русский.

```text
Составь тест-кейсы для проверки переходов состояний (state transition testing).

Сущность: [НАЗВАНИЕ]
Состояния: [СПИСОК ВСЕХ СОСТОЯНИЙ]
Разрешённые переходы: [ОПИСАНИЕ МАШИНЫ СОСТОЯНИЙ]
Бизнес-правила: [ОПИСАНИЕ ПРАВИЛ]

Создай тест-кейсы для:
- валидных переходов между состояниями;
- попыток невалидных переходов;
- действий, доступных только в определённом состоянии;
- условных переходов;
- сценариев отката (rollback).
```

## 3. Таблица принятия решений (Decision Table)

**Зачем:** покрыть комбинации бизнес-условий и отсечь невозможные — для правил расчётов, скидок, доступа.

**Источник:** [«15 промптов ChatGPT для QA», Хабр](https://habr.com/ru/articles/986376/) — структура промпта воспроизведена на русском.

```text
Построй таблицу принятия решений (decision table) и тест-кейсы по ней.

Функция или бизнес-правило: [ОПИСАНИЕ ЛОГИКИ, НАПРИМЕР РАСЧЁТА СКИДКИ]
Условия: [СПИСОК УСЛОВИЙ]
Действия: [СПИСОК ВОЗМОЖНЫХ ДЕЙСТВИЙ]

Задачи:
1. Перечисли все комбинации условий.
2. Исключи логически невозможные комбинации — с объяснением, почему каждая из них невозможна.
3. Для каждой валидной комбинации укажи ожидаемое действие и подготовь тестовые данные.

Формат: Markdown-таблица условий и действий + список тест-кейсов.
```
