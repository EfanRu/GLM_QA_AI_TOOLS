# Негативные сценарии и edge cases

Промпты для «атаки» на ввод: пустые и невалидные значения, спецсимволы, инъекции, ловушки с датами.

> **Как использовать:** скопируйте промпт, замените плейсхолдеры в `[КВАДРАТНЫХ СКОБКАХ]`. Результат всегда проверяйте — финальное слово за тестировщиком.

---

## 1. Пустые и нулевые значения (null/empty)

**Зачем:** проверить, как система различает null, пустую строку, пробелы и ноль — классовый источник багов.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/test-case-creation/edge-case-prompts.md`, промпт «Null and Empty Value Testing» — переведено на русский.

```text
Составь edge-case тест-кейсы для проверки обработки null и пустых значений.

Фича: [НАЗВАНИЕ]
Поля: [СПИСОК ВСЕХ ПОЛЕЙ]
Обязательные поля: [СПИСОК]
Опциональные поля: [СПИСОК]

Создай тест-кейсы для:
- null в обязательных полях;
- null в опциональных полях;
- разницы между пустой строкой и null;
- значений из одних пробелов;
- нуля в числовых полях;
- пустых массивов/коллекций;
- null-ссылок на объекты.
```

---

## 2. Спецсимволы и попытки инъекций

**Зачем:** проверить устойчивость ввода к SQL-инъекциям, XSS, unicode-сюрпризам и управляющим символам.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/test-case-creation/edge-case-prompts.md`, промпт «Special Character Handling» — переведено на русский.

```text
Составь edge-case тест-кейсы для проверки обработки спецсимволов.

Поля ввода: [СПИСОК ПОЛЕЙ]
Разрешённые символы: [ОПИСАНИЕ]

Проверь ввод со следующими категориями данных:
- символы SQL-инъекций (' -- ;);
- символы XSS (< > <script>);
- unicode-символы: эмодзи, спецсимволы, иероглифы, арабский язык;
- escape-последовательности (\n, \t, \r);
- символы path traversal (../ ..\);
- символы URL-кодирования (%20 %3C);
- управляющие символы.

Для каждой категории укажи ожидаемое поведение: корректная обработка, валидационная ошибка или экранирование.
```

## 3. Ловушки с датами и временем

**Зачем:** календарные крайние случаи — високосные годы, переходы на летнее время, таймзоны.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/test-case-creation/edge-case-prompts.md`, промпт «Time and Date Edge Cases» — переведено на русский.

```text
Составь edge-case тест-кейсы для проверки обработки дат и времени.

Фича: [НАЗВАНИЕ]
Поля даты/времени: [СПИСОК ПОЛЕЙ]
Обработка таймзон: [ДА/НЕТ]

Создай тест-кейсы для:
- високосных дат (29 февраля);
- конца месяца (28, 29, 30, 31 число);
- переходов на летнее/зимнее время;
- конвертации таймзон;
- дат из прошлого и далеко в будущем;
- невалидных дат (30 февраля, 13-й месяц);
- разных форматов дат;
- полночи и последней секунды дня (23:59:59).
```
