# Баг-репорты

Промпты для превращения черновых заметок в качественные баг-репорты: полный репорт, оценка severity/priority, описание плавающих багов.

> **Как использовать:** скопируйте промпт, замените плейсхолдеры в `[КВАДРАТНЫХ СКОБКАХ]`. Результат всегда проверяйте — финальное слово за тестировщиком.

---

## 1. Полный баг-репорт из заметок

**Зачем:** из черновика «не работает кнопка» получить структурированный репорт, готовый для Jira/YouTrack.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/bug-reporting/defect-description-prompts.md`, промпт «Comprehensive Bug Report Generation» + шаблон репорта из того же файла — переведено на русский.

```text
Помоги составить полный баг-репорт по обнаруженной проблеме.

Что я наблюдал: [ОПИСАНИЕ]
Где произошло: [МОДУЛЬ / СТРАНИЦА / ФИЧА]
Когда: [ДАТА И ВРЕМЯ]
Окружение: [БРАУЗЕР / ОС / ВЕРСИЯ ПРИЛОЖЕНИЯ]

Составь баг-репорт со следующими секциями:
- заголовок: краткий и информативный (что происходит и где);
- подробное описание;
- шаги воспроизведения по пунктам;
- ожидаемый и фактический результат;
- оценка влияния на пользователя и бизнес;
- рекомендуемые severity и priority с обоснованием;
- предлагаемый компонент/категория.

Дополнительно укажи: частоту воспроизведения (всегда/иногда/редко), workaround, если есть, и что стоит приложить (скриншоты, логи, видео).
```

## 2. Оценка Severity и Priority

**Зачем:** обоснованно выставить severity и priority — и объяснить разницу между ними для конкретного бага.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/bug-reporting/defect-description-prompts.md`, промпты «Bug Severity Assessment» и «Bug Priority Determination» — объединено и переведено на русский.

```text
Помоги определить severity и priority для бага.

Описание проблемы: [ОПИСАНИЕ]
Кого и как это затрагивает: [ВЛИЯНИЕ]
Обходной путь (workaround): [ЕСТЬ/НЕТ — ОПИСАТЬ]
Частота воспроизведения: [КАК ЧАСТО]
Доля затронутых пользователей: [% ИЛИ ЧИСЛО]
Ближайший релиз: [ДАТА ИЛИ ВЕРСИЯ]

Оцени:
1. Severity: Critical/Blocker, Major/High, Minor/Medium, Trivial/Low — с обоснованием.
2. Priority: P0–P4 — с учётом бизнес-критичности, влияния на пользователей и сроков релиза.

Объясни разницу между severity и priority применительно к этому конкретному багу.
```

## 3. Плавающий (нестабильный) баг

**Зачем:** описать баг, который воспроизводится через раз, так, чтобы разработчик мог с ним работать.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/bug-reporting/defect-description-prompts.md`, промпт «Intermittent Bug Description» — переведено на русский.

```text
Помоги описать нестабильный (плавающий) баг.

Проблема: [ОПИСАНИЕ]
Частота: [N РАЗ ИЗ M ПОПЫТОК]
Наблюдаемые закономерности: [КОГДА ПРОЯВЛЯЕТСЯ ЧАЩЕ]
Переменные, которые менялись при проверках: [УСЛОВИЯ]

Составь описание, которое:
- фиксирует нестабильную природу бага и статистику воспроизведения;
- перечисляет условия, при которых баг появляется и не появляется;
- описывает уже предпринятые попытки отладки;
- предлагает возможные причины и что проверить дальше.
```
