# Регрессия и чек-листы

Промпты для формирования регрессионного набора, приоритизации при нехватке времени и проверки UI.

> **Как использовать:** скопируйте промпт, замените плейсхолдеры в `[КВАДРАТНЫХ СКОБКАХ]`. Результат всегда проверяйте — финальное слово за тестировщиком.

---

## 1. Регрессионный набор под изменения

**Зачем:** собрать регрессионный набор, привязанный к конкретным изменениям релиза.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/test-case-creation/regression-prompts.md`, промпт «Regression Suite Generation» — переведено на русский.

```text
Мне нужно составить регрессионный набор тестов для [НАЗВАНИЕ_ПРИЛОЖЕНИЯ].

Недавние изменения: [ОПИСАНИЕ ИЗМЕНЕНИЙ]
Затронутые модули: [СПИСОК]
Исторические проблемы: [ОПИСАНИЕ ПРОШЛЫХ БАГОВ]

Составь регрессионный набор, который:
- покрывает ключевую функциональность;
- проверяет точки интеграции;
- валидирует критичные пользовательские пути;
- ловит побочные эффекты недавних изменений;
- включает smoke-тесты для быстрой проверки.

Приоритизируй тест-кейсы по риску и влиянию.
```

---

## 2. Приоритизация регресса при нехватке времени

**Зачем:** выбрать, что бежать в первую очередь, когда времени на полный регресс нет.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/test-case-creation/regression-prompts.md`, промпт «Regression Test Prioritization» — переведено на русский.

```text
У меня есть [ЧИСЛО] регрессионных тест-кейсов. Помоги приоритизировать их для релиза с ограниченным временем тестирования.

Объём релиза: [ОПИСАНИЕ]
Доступное время: [ОГРАНИЧЕНИЕ]
Список тест-кейсов: [СПИСОК ИЛИ КРАТКОЕ ОПИСАНИЕ]

Приоритизируй по критериям:
- бизнес-критичность;
- частота использования;
- история дефектов;
- близость к недавним изменениям кода;
- влияние на клиентов.

Раздели тесты на три группы:
1. Must-run (критический путь);
2. Should-run (важные фичи);
3. Nice-to-run (низкий приоритет).
```

## 3. Чек-лист проверки UI

**Зачем:** системный чек-лист UI-проверок для страницы — от раскладки до сообщений об ошибках.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/checklist-prompts/ui-checklist.md`, промпт «General UI Testing Checklist» — переведено на русский.

```text
Составь полный чек-лист UI-тестирования для:

Приложение: [НАЗВАНИЕ]
Страница/экран: [НАЗВАНИЕ]
Браузеры: [СПИСОК БРАУЗЕРОВ]

Чек-лист должен покрывать:
- раскладку и адаптивность (responsive);
- навигацию и ссылки;
- формы и валидацию ввода;
- визуальные элементы (цвета, шрифты, изображения);
- интерактивные элементы (кнопки, дропдауны);
- сообщения об ошибках и уведомления;
- доступность (a11y);
- кросс-браузерную совместимость.

Формат — чек-боксы, сгруппированные по разделам.
```
