# Удобство использования и доступность

Промпты для usability-тестирования и проверки доступности (a11y/WCAG).

> **Как использовать:** скопируйте промпт, замените плейсхолдеры в `[КВАДРАТНЫХ СКОБКАХ]`. Результат всегда проверяйте — финальное слово за тестировщиком.

---

## 1. План usability-тестирования

**Зачем:** спланировать юзабилити-сессию: задачи участникам, метрики успеха, вопросник.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/usability-testing/usability-testing-prompts.md`, промпт «Usability Test Plan» — переведено на русский.

```text
Составь план usability-тестирования.

Продукт: [НАЗВАНИЕ]
Целевые пользователи: [ПЕРСОНЫ]
Ключевые фичи: [СПИСОК]
Что оцениваем: [ЦЕЛИ ТЕСТИРОВАНИЯ]

План должен включать:
- цели тестирования;
- критерии отбора участников;
- сценарии задач для участников;
- метрики успеха;
- рекомендации по наблюдению за сессией;
- пост-тестовый опросник;
- фреймворк анализа результатов.

Формат: структурированный документ-план.
```

---

## 2. Проверка цветового контраста (WCAG)

**Зачем:** системная проверка контраста всех текстовых и графических элементов по требованиям WCAG 2.1.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `automation-qa/accessibility-testing/wcag-compliance-prompts.md`, промпт «Color Contrast Testing» — переведено на русский (сокращено).

```text
Составь план проверки цветового контраста для приложения.

Приложение: [НАЗВАНИЕ]
Цветовая палитра: [СПИСОК ЦВЕТОВ]

Требования WCAG 2.1:
1. Обычный текст (< 18pt или < 14pt bold): контраст не менее 4.5:1.
2. Крупный текст (≥ 18pt или ≥ 14pt bold): не менее 3:1.
3. Графические объекты и компоненты UI: не менее 3:1.

Составь тест-кейсы для:
- основного текста на фоне;
- заголовков;
- ссылок (обычные, посещённые, hover, focus);
- текста кнопок на фоне кнопки;
- текста в полях формы;
- плейсхолдеров (обязаны соответствовать 4.5:1);
- сообщений об ошибках, успехе и предупреждениях;
- иконок, границ полей, индикаторов фокуса, графиков.

Для каждого случая укажи: элемент, требуемое соотношение и инструмент проверки (WebAIM Contrast Checker, Colour Contrast Analyser, Chrome DevTools).
```

## 3. Баг-репорт по доступности (a11y)

**Зачем:** описать барьер доступности со ссылкой на нарушенную рекомендацию WCAG — язык, понятный разработке.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/bug-reporting/defect-description-prompts.md`, промпт «Accessibility Bug Description» — переведено на русский.

```text
Помоги составить баг-репорт по проблеме доступности.

Уровень WCAG: [A / AA / AAA]
Тип проблемы: [КЛАВИАТУРНАЯ НАВИГАЦИЯ / СКРИНРИДЕР / КОНТРАСТ и т.д.]
Затронутый элемент: [ОПИСАНИЕ]
Нарушенная рекомендация: [НОМЕР РЕКОМЕНДАЦИИ WCAG, ЕСЛИ ИЗВЕСТЕН]

Включи:
- описание барьера доступности;
- ссылку на рекомендацию WCAG;
- группы пользователей, которых это затрагивает;
- текущее поведение;
- ожидаемое доступное поведение;
- использованный инструмент тестирования (axe, Lighthouse, скринридер и т.п.).
```
