# API-тестирование

Промпты для ручного API-тестирования: чек-лист по REST API, генерация Postman-коллекции и API-регресс.

> **Как использовать:** скопируйте промпт, замените плейсхолдеры в `[КВАДРАТНЫХ СКОБКАХ]`. Результат всегда проверяйте — финальное слово за тестировщиком.

---

## 1. Чек-лист проверки REST API

**Зачем:** системно проверить API без пропусков — методы, статус-коды, аутентификация, ошибки.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/checklist-prompts/api-checklist.md`, промпт «REST API Testing Checklist» — переведено на русский.

```text
Составь полный чек-лист тестирования REST API для:

API: [НАЗВАНИЕ]
Base URL: [АДРЕС]
Аутентификация: [ТИП]
Количество эндпоинтов: [ЧИСЛО]
Версия API: [ВЕРСИЯ]

Чек-лист должен покрывать:
- функциональность эндпоинтов;
- HTTP-методы (GET, POST, PUT, DELETE, PATCH);
- валидацию запросов и ответов;
- статус-коды;
- аутентификацию и авторизацию;
- обработку ошибок;
- производительность;
- безопасность.

Формат — чек-боксы, сгруппированные по разделам.
```

---

## 2. Postman-коллекция из Swagger/OpenAPI

**Зачем:** из спецификации получить готовую коллекцию с позитивными и негативными кейсами и тест-скриптами.

**Источник:** [«15 промптов ChatGPT для QA», Хабр](https://habr.com/ru/articles/986376/) — структура промпта воспроизведена на русском.

```text
Создай Postman-коллекцию для тестирования API.

Контекст: [REST/GraphQL, ТИП АУТЕНТИФИКАЦИИ, BASE URL]
Спецификация Swagger/OpenAPI: [ВСТАВИТЬ ИЛИ ПРИЛОЖИТЬ ССЫЛКУ]

Требования к коллекции:
- покрыть CRUD и позитивные/негативные сценарии, граничные случаи, тесты аутентификации;
- использовать переменные окружения;
- структура — папки по ресурсам;
- нейминг запросов вида «POST /users — создание пользователя с валидными данными»;
- pre-request и test-скрипты: проверка статус-кода, валидация схемы, время ответа, ключевые поля.

Вывод: JSON коллекции (Postman Collection v2.1), описания запросов, примеры body, шаблон окружения (base_url, api_token, user_id) и инструкция по запуску.
```

## 3. API-регрессионный набор

**Зачем:** проверить, что изменения API не сломали существующих потребителей.

**Источник:** [qa-prompt-library (106 ★)](https://github.com/tayyabakmal1/qa-prompt-library) → `manual-qa/test-case-creation/regression-prompts.md`, промпт «API Regression Testing» — переведено на русский.

```text
Составь API-регрессионный набор тестов.

Тип API: [REST/GRAPHQL/SOAP]
Изменённые эндпоинты: [СПИСОК]
Breaking changes: [ДА/НЕТ — ОПИСАТЬ ЕСЛИ ЕСТЬ]

Сгенерируй тест-кейсы для:
- функциональности существующих эндпоинтов;
- валидации схемы ответа;
- обработки ошибок;
- аутентификации и авторизации;
- rate limiting;
- обратной совместимости (backward compatibility);
- контрактных сценариев.
```
